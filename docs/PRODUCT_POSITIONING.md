# EBED Studio 产品定位

## 已确定的方向

核心产品是独立可用的嵌入式调试软件，面向嵌入式与无线开发工程师的日常工作。自有 dongle 是提高套餐价值的可选配件，首版聚焦 Wi-Fi 抓包。用户已有串口、网络接口与采集文件应直接产生使用价值。

GUI 使用 HTML/React 实现，由桌面运行环境统一提供串口、网络和文件能力。最终用户双击程序使用，不承担开发环境的安装与配置；目标设备的波特率、地址等业务参数仍由界面设置。

## 软件与配件的边界

| 产品或能力 | 定位 | 交付边界 |
| --- | --- | --- |
| EBED Studio 软件 | 独立产品 | 串口、TCP/UDP、MQTT、协议分析、日志、脚本和会话工作流；无需购买自有硬件 |
| Wi-Fi dongle | 可选增值配件，可与软件组成套餐 | 提供经验证的空口采集、USB 传输、出厂固件和接入体验 |
| 逻辑分析、SPI/I²C | 软件中的独立工具能力 | 实时输入/输出需要实际采样或总线接口；不规定必须集成在 Wi-Fi dongle 上 |
| BLE / Bluetooth | 无线能力的后续扩展 | 扫描、连接抓包与不同 PHY 的范围分别验证，不因装有蓝牙芯片就宣称全协议抓包 |
| 第三方适配器 | 兼容方向 | 使用各厂商实际协议接入；目前只实现普通串口和 EBP 后端，不能宣称通用兼容 |

没有 Wi-Fi 抓包硬件时，实时空口采集不可执行；串口、网络及离线分析保持可用。功能可用性取决于真实数据源和接口能力，不以是否插入自有 dongle 作为软件授权判断。

## 商业交付

软件应以调试效率、稳定收发、协议理解、复现与记录形成独立购买理由。Wi-Fi 配件通过实际采集能力、出厂配置、接线便利、质量验证与配套支持增加套餐价值。

软件单独交付和软件加配件套餐都应成立。软件是否免费、授权方式、具体定价和售后范围尚未确定；当前不增加付费墙、dongle 激活、购买页面或未经确认的收费机制。商业策略保留在产品文档中，用户界面展示任务、可用工具和配件能力。

## 界面与工程原则

- 首页优先呈现串口、网络、日志与会话入口；Wi-Fi 配件放在可选扩展位置。
- 普通串口无需 EBED 固件、厂商身份或握手。EBP/1 扩展设备通过用户明确选择后连接，能力按固件实际报告启用。
- 采集数据、协议解码、日志与界面应独立于硬件实现；新增适配后端不重写上层工作流。
- Wi-Fi dongle 首版只需 Wi-Fi 能力；BLE、数字探头、RS485 和逻辑采样不阻塞其首版交付。
- 软件的真实串口/网络联调、稳定性与工作流完善优先推进；Wi-Fi 硬件与固件并行研发，各自验收。

当前已有工作台、普通串口 UART/Modbus、网络工具箱、协议解码、采集会话和 EBP 主机实现。尚待完成的真实硬件联调、第三方适配、固件交付与发布签名继续按验证文档跟踪。
